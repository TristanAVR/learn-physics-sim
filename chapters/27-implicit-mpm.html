Implicit MPM

Ask the end of the step: backward Euler on the grid, solved as a minimisation with Newton's method, conjugate gradients and a line search.

Explicit MPM has a speed limit, and you found it in the last two chapters: the time step must stay below about $\Delta x / c$, where $c$ is the speed of sound in the material. A jelly with a Young's modulus of 1 MPa has $c$ = 36.7 m/s, so on our 64-cell grid each step can be at most 0.43 ms, which means 39 steps for every frame you draw. Make the jelly ten times stiffer and you need three times as many.

The time integration chapter offered a way out for a single spring: implicit Euler, which evaluates the force at the end of the step and is stable for any $h$. This chapter does the same for MPM. The unknown is now every grid velocity at once, coupled through every particle, so "solve for the end of the step" becomes a nonlinear system with thousands of unknowns. You will solve it the way modern MPM codes do: as a minimisation, with Newton's method, a conjugate gradient solver that never builds a matrix, and a line search that guarantees progress.

By the end you will be able to write backward Euler MPM, implement matrix-free CG and a Newton loop with a backtracking line search, explain why the stiffness matrix can stop being positive definite and what to do about it, judge when implicit is worth its cost, and read section 11 of the MPM course notes.

Backward Euler on the grid

Recall the explicit grid update of chapter 25, written with the force at the current configuration:

$$m_i\big(v_i^{n+1} - v_i^n\big) = h\,f_i(x^n) + h\,m_i\,g.$$

Backward Euler asks for the force at the end of the step instead. The grid does not really move, but in chapter 25's energy derivation we imagined it moving, node $i$ to $\hat x_i = x_i + h\,v_i$, and every particle's deformation gradient following it. Evaluate the force at the positions the new velocities would produce:

$$m_i\big(v_i^{n+1} - v_i^n\big) = h\,f_i\big(\hat x(v^{n+1})\big) + h\,m_i\,g, \qquad \hat x_i = x_i + h\,v_i^{n+1}.$$

Everything we need was built in chapter 25. With the shorthand $q_{ip} = \mathbf F_p^T \nabla w_{ip}$ (a vector per particle and node, fixed during the step), the deformation gradient the step would produce and the force it would cause are

$$\hat{\mathbf F}_p(v) = \mathbf F_p + h\sum_j v_j\,q_{jp}^T, \qquad f_i(v) = -\sum_p V_p^0\,\mathbf P\big(\hat{\mathbf F}_p(v)\big)\,q_{ip}.$$

The first is $(\mathbf I + h\nabla v_p)\mathbf F_p$ written out; the second is chapter 25's force with $\hat{\mathbf F}_p$ in place of $\mathbf F_p$. The catch is the usual one: $v^{n+1}$ appears on both sides, inside a nonlinear stress, and through the particles every node is coupled to its neighbours. For the demo's beam of 900 particles that is a system of about 600 coupled nonlinear equations (two per active grid node) every step.

The demo runs a stiff jelly beam, clamped in the left wall, at one step per frame: $h$ = 16.7 ms, so $hc/\Delta x = 39$, far beyond anything explicit MPM survives. Switch to explicit and it explodes on the first frame. Switch to the jelly drop and watch two blocks land; the readouts show how hard the solver works for each step.

A minimisation in disguise

Gast and colleagues (Optimization Integrator for Large Time Steps, 2015) observed that this system is the condition for the minimum of a scalar function. Let $v^* = v^n + h g$ be the velocity the grid would have with gravity alone, and define the incremental potential

$$E(v) = \sum_i \tfrac12\,m_i\,\big|v_i - v_i^*\big|^2 \;+\; \Phi\big(\hat x(v)\big), \qquad \Phi = \sum_p V_p^0\,\Psi\big(\hat{\mathbf F}_p(v)\big).$$

Its gradient is

$$\frac{\partial E}{\partial v_i} = m_i\,(v_i - v_i^*) + h\,\frac{\partial\Phi}{\partial\hat x_i} = m_i\,(v_i - v_i^*) - h\,f_i(v),$$

because $\partial\hat x_i/\partial v_i = h$ and the force is minus the gradient of the elastic energy (chapter 25). Setting it to zero gives back exactly the backward Euler update. So one implicit step is one minimisation: find the velocities that best balance staying close to $v^*$ (the kinetic term, inertia) against relaxing the elastic energy at the end of the step.

This is the same idea as the energy view of XPBD in the compliance chapter, and it buys three things. The problem has a natural measure of progress: $E$ must go down, so a bad step can be detected and shortened. The Hessian, the matrix of second derivatives, is symmetric, so we can use conjugate gradients. And as long as every step lowers $E$, the solver cannot blow up, whatever the time step: the energy is bounded below.

Units check. $E$ has units of energy (J per metre of depth in 2D): $m_i |v|^2$ is kinetic energy and $\Phi$ is elastic energy. Dividing the gradient by $m_i$ gives a velocity error, $v_i - v_i^* - h f_i/m_i$, which is how the demo measures convergence: the readout "residual" is the mass-weighted RMS of that error, in m/s, and Newton stops below $10^{-3}$ m/s.

Newton's method

Newton's method replaces $E$ near the current guess $v$ by its quadratic Taylor model and jumps to the model's minimum:

$$E(v + d) \approx E(v) + g^T d + \tfrac12\,d^T \mathbf H\,d \quad\Longrightarrow\quad \mathbf H\,d = -g,$$

where $g$ is the gradient and $\mathbf H$ the Hessian of $E$:

$$\mathbf H = \mathbf M + h^2\,\mathbf K, \qquad \mathbf K = \frac{\partial^2\Phi}{\partial\hat x\,\partial\hat x}.$$

$\mathbf M$ is the diagonal matrix of node masses and $\mathbf K$ is the stiffness matrix, the derivative of minus the forces with respect to node positions. The $h^2$ is the whole story of implicit integration in one symbol: for a small step the mass dominates and $\mathbf H$ is easy, for a large step the stiffness dominates and $\mathbf H$ becomes as hard to invert as the elastic problem itself.

Start from $v = v^*$ (no elastic forces), solve for $d$, update $v \leftarrow v + d$, repeat. Near the solution Newton converges quadratically: the number of correct digits roughly doubles every iteration. In the cantilever, the residual goes 7.8, 0.25, 0.0003, 0.0000003 m/s in three iterations. Two are enough for our tolerance.

Hessian-vector products without a matrix

We never build $\mathbf H$. A thousand unknowns would make a matrix of a million entries, most of them zero, and in 3D MPM codes the unknowns run into millions. What we can do cheaply is multiply $\mathbf H$ by a vector $u$, and that turns out to be all a conjugate gradient solver needs.

Think of $u$ as a small change of the grid velocities. It changes every particle's deformation gradient by

$$\delta\mathbf F_p = \sum_j u_j\, q_{jp}^T,$$

which is a G2P-like gather. That changes the particle's stress by $\delta\mathbf P_p = \frac{\partial\mathbf P}{\partial\mathbf F}(\hat{\mathbf F}_p) : \delta\mathbf F_p$, the derivative of the stress in the direction $\delta\mathbf F_p$. And that changes the forces by a P2G-like scatter. Putting the $h$ factors in,

$$(\mathbf H u)_i = m_i\,u_i \;+\; h^2\sum_p V_p^0\;\delta\mathbf P_p\;q_{ip}.$$

One Hessian-vector product costs one gather and one scatter over the particles, about the cost of one explicit step. For fixed corotated, the stress differential follows from $\mathbf P = 2\mu(\mathbf F - \mathbf R) + \lambda(J-1) \operatorname{cof}\mathbf F$, with $\operatorname{cof}\mathbf F = J\mathbf F^{-T}$:

$$\delta\mathbf P = 2\mu\,(\delta\mathbf F - \delta\mathbf R) + \lambda\,(\operatorname{cof}\mathbf F : \delta\mathbf F)\, \operatorname{cof}\mathbf F + \lambda\,(J - 1)\,\operatorname{cof}(\delta\mathbf F).$$

Two pieces need a moment's thought. In 2D, $\operatorname{cof}\mathbf F$ is linear in the entries of $\mathbf F$, so its differential is $\operatorname{cof}(\delta\mathbf F)$, and $\operatorname{cof}\mathbf F : \delta\mathbf F$ is the change of $J$. The rotation is the hard part in 3D, but in 2D $\mathbf R$ is the rotation by $\theta = \operatorname{atan2}(b, a)$ with $a = F_{00} + F_{11}$, $b = F_{10} - F_{01}$, so

$$\delta\theta = \frac{a\,\delta b - b\,\delta a}{a^2 + b^2}, \qquad \delta\mathbf R = \delta\theta\begin{pmatrix} -s & -c \\ c & -s\end{pmatrix}.$$ 
function hessVec(u, out) {
  out.fill(0);                                           // out = M u on the free degrees of freedom
  for (let f = 0; f < nFree; f++) { const i = freeList[f]; out[i] = gm[i >> 1] * u[i]; }
  for (let p = 0; p < count; p++) {
    let d00 = 0, d01 = 0, d10 = 0, d11 = 0;              // dF = sum_j u_j q_j^T   (gather)
    for (let k = 9 * p; k < 9 * p + 9; k++) {
      const i = 2 * sNode[k];
      d00 += u[i] * sQx[k]; d01 += u[i] * sQy[k]; d10 += u[i + 1] * sQx[k]; d11 += u[i + 1] * sQy[k];
    }
    stressDifferential(/* F_hat, R */ ..., d00, d01, d10, d11, mu, la, P);   // dP
    const V = pV0[p] * h * h;
    for (let k = 9 * p; k < 9 * p + 9; k++) {             // out += h^2 V dP q   (scatter)
      const i = 2 * sNode[k];
      out[i] += V * (P[0] * sQx[k] + P[1] * sQy[k]);
      out[i + 1] += V * (P[2] * sQx[k] + P[3] * sQy[k]);
    }
  }
}

Test the derivative before you trust it. A wrong sign in $\delta\mathbf P$ does not crash anything; Newton just converges slowly or not at all. Compare $\mathbf H u$ with the central difference $\big(g(v + \epsilon u) - g(v - \epsilon u)\big)/(2\epsilon)$ for random $v$ and $u$, on the free degrees of freedom only. For the demo's hessVec, with $\epsilon = 10^{-5}$, the two agree to a relative error of $2\times10^{-11}$, in both scenes, mid-motion. Do the same for the gradient against the energy.

Conjugate gradients

The linear system $\mathbf H d = -g$ is solved with the conjugate gradient method (CG), which you met in the linear solvers chapter. It is the right tool because it needs only products $\mathbf H p$, and it is guaranteed to work when $\mathbf H$ is symmetric positive definite. Each iteration minimises the quadratic model over one more search direction, chosen so that it does not undo the progress of the previous ones.

// Preconditioned CG for H x = b (x starts at 0). z = r / diagH is the Jacobi preconditioner.
r = b;  z = r / diagH;  p = z;  rz = r . z
repeat:
  Ap = H p;  pAp = p . Ap
  if (pAp <= 0) stop                      // negative curvature: see below
  alpha = rz / pAp
  x += alpha p;  r -= alpha Ap
  if (|r| < relTol |b|) stop
  z = r / diagH;  rzNew = r . z
  p = z + (rzNew / rz) p;  rz = rzNew

The preconditioner matters more in MPM than almost anywhere. Node masses vary enormously: a node deep inside the material has the full mass of its neighbourhood, a node at the surface may receive one percent of it. Plain CG treats all unknowns alike and crawls. Dividing the residual by the diagonal of $\mathbf H$, which the code approximates as $m_i$ plus $h^2$ times the diagonal of a linear-elastic stiffness, puts every node on an equal footing at the cost of one division.

How many iterations? CG's convergence depends on the condition number of the (preconditioned) matrix, roughly iterations $\propto \sqrt{\kappa}$. For $\mathbf M + h^2\mathbf K$, the stiffest mode against the mass gives $\kappa \sim (hc/\Delta x)^2$, so you should expect iteration counts proportional to $hc/\Delta x$, that is, to $h\sqrt E$. Once $h^2\mathbf K$ dominates $\mathbf M$ completely, the count stops growing: the matrix is then essentially $h^2\mathbf K$, whose condition number depends on the shape of the body and the grid, not on $E$. Exercise 4 measures both regimes.

When the Hessian is not positive definite

CG assumes $\mathbf H$ is positive definite: $u^T\mathbf H u > 0$ for every direction $u$, so that the quadratic model has a minimum. The mass part always is. The stiffness part need not be. A material's energy is convex near its rest shape, but fixed corotated is not convex everywhere: under strong compression the $\lambda(J-1)\operatorname{cof} (\delta\mathbf F)$ term contributes negative curvature, and so does the rotation term when $\mathbf F$ is far from a rotation. Physically, the material is in a state where pushing harder makes it give way, like a column buckling. Mathematically, the quadratic model has no minimum in some direction, and Newton's step can point uphill.

There are three standard defences, and robust codes use more than one:

  • Stop CG at negative curvature. If CG meets a direction with $p^T\mathbf H p \le 0$, it stops and returns what it has so far (or, on the first iteration, the preconditioned steepest descent direction). Everything it returns is then a descent direction. This "truncated CG" is what our cg does, and it costs nothing.
  • Make each particle's Hessian positive definite. $\mathbf K$ is a sum of per-particle contributions. Smith, De Goes and Kim (Analytic Eigensystems for Isotropic Distortion Energies, 2019) give the eigenvalues and eigenvectors of $\partial^2\Psi/\partial\mathbf F^2$ in closed form for isotropic energies, so each negative eigenvalue can be clamped to zero before the contributions are summed. The projected Hessian is positive definite by construction.
  • Check the step with the energy. The line search below rejects any step that does not lower $E$ enough, whatever produced it.

why PB-MPM's introduction mentions this

The PB-MPM paper motivates itself with exactly this section: implicit integration via Newton allows large steps, it says, but it is complex to implement and has its own stability pitfalls, such as needing a positive definite stiffness matrix, citing Smith et al. 2019. Now you know what that sentence means, and why a method with no Hessian at all is attractive for games. The next chapter builds it.

A line search makes Newton safe

Even with a good direction, the full Newton step can be too long. The quadratic model is only accurate near the current guess, and at the moment two stiff blocks collide the true energy is far from quadratic. The fix is to treat $d$ as a direction and choose how far to go. Backtracking starts with the full step $\alpha = 1$ and halves it until the energy has decreased enough:

$$E(v + \alpha d) \;\le\; E(v) + c\,\alpha\,g^T d, \qquad c = 10^{-4}.$$

This is the Armijo condition: the decrease must be at least a small fraction of what the linear model predicts. Since $g^T d < 0$ for a descent direction, a small enough $\alpha$ always satisfies it. Each test costs one energy evaluation, a gather over the particles, which is cheap next to the CG solve.

let alpha = 1;
for (let ls = 0; ls < 30; ls++) {
  for (let i = 0; i < NDOF; i++) vTry[i] = vel[i] + alpha * dir[i];
  if (energy(vTry) <= E0 + 1e-4 * alpha * gd) break;
  alpha *= 0.5;
}
vel.set(vTry);

How much does it matter? In the cantilever, never: the full step is always accepted. In the jelly drop at the demo's settings, one Newton step from $v^*$ without a line search sends particles flying at 40,000 m/s the moment the blocks land, while Newton with the line search needs up to a dozen halvings in the steps around impact and stays calm. At $E$ = 10 MPa and $h$ = 33 ms, full Newton steps without the line search explode; with it, the drop is stable, at the price of about three halvings per step.

Explicit, semi-implicit, implicit

The implicit beam also gives two checks against closed forms. First, statics. Euler-Bernoulli beam theory for a cantilever of length $L$ and thickness $t$ under its own weight, in plane strain ($E' = E/(1-\nu^2)$), predicts a tip deflection $\delta = \frac{3\rho g L^4}{2E't^2}$ = 8.37 cm for the demo's $L$ = 0.5 m, $t$ = 0.1 m, $E$ = 1 MPa, plus about 0.38 cm of shear deflection for so thick a beam: 8.75 cm. The simulation settles at 10.4 cm. Is that an error in the solver or in the discretisation? Rerunning the same beam on grids of 32, 64 and 128 cells gives 13.7, 10.4 and 9.3 cm: the error shrinks about threefold for each halving of $\Delta x$, and extrapolating gives 8.7 cm. So the solver is right, and the beam, with only six cells through its thickness, is a little too soft at this resolution.

Second, dynamics. Press kick and the beam oscillates with a period of 0.52 s (beam theory says 0.47 s for the stiffer continuum beam; the 25 % extra softness predicts $0.47\times\sqrt{1.25}$ = 0.52 s). The oscillation dies out, and how fast depends on $h$, exactly as chapter 04 predicted for implicit Euler: each step multiplies the amplitude by $1/\sqrt{1 + h^2\omega^2}$. With $\omega = 2\pi/0.52$ s = 12.2 rad/s, that is a factor 0.53 per period at $h$ = 16.7 ms and 0.93 at $h$ = 2 ms. We measured 0.47 and 0.85: the predicted numerical damping, plus a further 8 % per period, at any step size, from MPM's transfers. Large implicit steps are stable because they damp, and the damping is visible.

What it costs

Count the work in particle passes (one gather or scatter over all particles). Explicit MPM at its limit of 0.43 ms needs 39 steps per frame, two passes each: about 80 passes. Implicit at one step per frame needs two or three Newton iterations, each with a gradient pass, a line search pass or two and 100 to 140 CG iterations of two passes each: about 500 passes. On this scene, with a Jacobi preconditioner, implicit is several times slower than explicit.

That is not a failure of the method; it is the honest trade-off. Implicit pays off when the material is so stiff that explicit would need hundreds of steps per frame while CG's iteration count has saturated (exercise 4), when a better preconditioner keeps CG's count low (multigrid methods are the usual choice; Wang et al., Hierarchical Optimization Time Integration for CFL-rate MPM Stepping, 2020, is a good example), and whenever robustness at a fixed large step matters more than raw speed. It also costs implementation effort: second derivatives of every material model, a careful treatment of definiteness, and a solver that must converge every step.

For real-time work, none of those are attractive. A game wants a fixed, small cost per step and no possibility of failure. The next chapter's method keeps the large stable step but drops the Hessian, the linear solve and the line search: it trades accuracy (softness when it has not converged) for a cost of roughly one explicit step per iteration.

function cg(b, x, maxIter, relTol) {
  x.fill(0); cgP.fill(0);
  for (let f = 0; f < nFree; f++) {
    const i = freeList[f];
    cgR[i] = b[i]; cgZ[i] = cgR[i] / diagH[i]; cgP[i] = cgZ[i];
  }
  let rz = dot(cgR, cgZ);
  const stop = relTol * relTol * dot(b, b);
  let k = 0;
  for (; k < maxIter; k++) {
    hessVec(cgP, cgAp);
    const pAp = dot(cgP, cgAp);
    if (pAp <= 0) {
      if (k === 0) for (let f = 0; f < nFree; f++) x[freeList[f]] = cgZ[freeList[f]];
      break;
    }
    const alpha = rz / pAp;
    for (let f = 0; f < nFree; f++) { const i = freeList[f]; x[i] += alpha * cgP[i]; cgR[i] -= alpha * cgAp[i]; }
    if (dot(cgR, cgR) < stop) { k++; break; }
    for (let f = 0; f < nFree; f++) { const i = freeList[f]; cgZ[i] = cgR[i] / diagH[i]; }
    const rzNew = dot(cgR, cgZ), beta = rzNew / rz;
    rz = rzNew;
    for (let f = 0; f < nFree; f++) { const i = freeList[f]; cgP[i] = cgZ[i] + beta * cgP[i]; }
  }
  return k;
}

Solution 
function newtonSolve() {
  for (let i = 0; i < NDOF; i++) vel[i] = vStar[i] * free[i];
  for (let it = 0; it < maxNewton.value; it++) {
    const E0 = energyAndGradient(vel, grad);
    stats.residual = residualNorm(grad);
    if (stats.residual < NEWTON_TOL) break;
    stats.newton++;
    for (let i = 0; i < NDOF; i++) vTry[i] = -grad[i];
    stats.cg += cg(vTry, dir, maxCG.value, 1e-3);
    let gd = dot(grad, dir);
    if (!(gd < 0)) {
      for (let i = 0; i < NDOF; i++) dir[i] = free[i] ? -grad[i] / diagH[i] : 0;
      gd = dot(grad, dir);
    }
    let alpha = 1;
    for (let ls = 0; ls < 30; ls++) {
      for (let i = 0; i < NDOF; i++) vTry[i] = vel[i] + alpha * dir[i];
      if (energy(vTry) <= E0 + 1e-4 * alpha * gd) break;
      alpha *= 0.5;
      stats.halvings++;
    }
    vel.set(vTry);
  }
  energyAndGradient(vel, grad);
  stats.residual = residualNorm(grad);
}

Summary

  • Backward Euler MPM evaluates grid forces at the moved node positions $\hat x_i = x_i + h v_i^{n+1}$; with $q_{ip} = \mathbf F_p^T\nabla w_{ip}$, $\hat{\mathbf F}_p = \mathbf F_p + h\sum_j v_j q_{jp}^T$.
  • The update is the minimum of the incremental potential $E(v) = \sum_i \frac12 m_i|v_i - v_i^*|^2 + \Phi(\hat x(v))$. Its gradient is $m(v - v^*) - hf$, its Hessian $\mathbf M + h^2\mathbf K$.
  • Newton's method solves $\mathbf H d = -g$ with matrix-free preconditioned CG: a Hessian-vector product is a gather of $\delta\mathbf F_p$, a stress differential, and a scatter.
  • The elastic Hessian can be indefinite. Truncate CG at negative curvature, project per-particle Hessians (Smith et al. 2019), and always check steps with a backtracking line search on $E$.
  • Implicit steps are stable at any size but add numerical damping, and with a simple preconditioner they are not necessarily cheaper than explicit ones.
