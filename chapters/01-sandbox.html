The Sandbox

A tiny library that handles windows, drawing and sliders, so you only write the physics.

Graphics tutorials spend their first chapters opening a window and setting up a render loop. We want to get to the physics quickly, so this site comes with a small library, code/lib/sandbox.js, that does all of that for you. It opens a canvas, runs a loop, draws shapes in metres instead of pixels, and gives you sliders, plots and the mouse. Every demo and every starter on the site uses it, so it is worth ten minutes to get comfortable with it.

This chapter has no physics. By the end of it you will have a dot moving on a circle, an arrow following your mouse and a live plot, and you will know where everything you need later lives.

Running a script

A simulation script is a single JavaScript file. To run one, open the runner page with the script's path:

code/run.html?src=01-sandbox/starter.js

The runner loads the sandbox and then your script. When you change the file, save and refresh the page. If a script throws an error, the sandbox pauses and prints the error over the canvas, with the line number, so you do not need the developer tools for the common mistakes (but they are a keypress away, F12 in most browsers, when you do).

The shape of a simulation

Every script has the same three functions and one call:

let state;

function reset() {          // build the initial state
  state = { x: 0, y: 1 };
}

function step(dt) {         // advance the state by dt seconds
  state.y -= 0.5 * dt;
}

function draw(g) {          // draw the current state
  g.circle(state.x, state.y, 0.05);
}

Sim.run({ title: 'My first sim', view: [-1, 0, 1, 1.5], reset, step, draw });

This split is not just tidiness; it mirrors how real simulators are built.

  • reset() creates the world. The sandbox calls it once at the start, again when you press R or the Reset button, and whenever a control marked { reset: true } changes. Keep all your initial values here, so a reset always gives the same starting point.
  • step(dt) moves the world forward by dt seconds. This is where all the physics goes. It must not draw anything, and it should not depend on how often the screen refreshes: the sandbox calls it with a fixed dt (1/60 s unless you choose otherwise), which, as you will see in the Time Integration chapter, matters a great deal.
  • draw(g) draws the world as it is now. It is called every frame, including while paused, so it must not change the state.

Sim.run starts the loop. Its options include the view, the rectangle of the world you want to see as [xmin, ymin, xmax, ymax] in metres, plus dt (a number, or a function such as () => slider.value) and stepsPerFrame, the number of step calls per drawn frame.

The header has Pause, Step and Reset buttons, also on the keyboard as Space, . and R. Single-stepping a simulation frame by frame is one of the best debugging tools there is; get used to it now.

Drawing in metres

The g passed to draw draws in world coordinates: metres, with y pointing up, the way physics is written. The sandbox fits your view into the canvas, keeping the aspect ratio, and converts for you. A circle of radius 0.05 is always 5 cm, whatever the window size.

g.circle(x, y, r, { fill: Sim.colors.blue });          // a filled disc of radius r metres
g.circle(x, y, r, { stroke: Sim.colors.red, width: 2 }); // an outline, 2 pixels wide
g.dot(x, y, 4, Sim.colors.ink);                          // a dot 4 pixels across at any zoom
g.line(x1, y1, x2, y2, { color: Sim.colors.ink, width: 1.5, dash: [4, 4] });
g.polyline(points, { color, closed: true, fill });       // points: [{x, y}, ...] or [x0, y0, x1, y1, ...]
g.rect(x, y, w, h, { fill });                             // (x, y) is the bottom-left corner
g.arrow(x, y, dx, dy, { color });                         // a vector, e.g. a force or a velocity
g.text('label', x, y, { color, size, align });
g.points(xs, ys, count, { radius: 2, color });            // thousands of particles from flat arrays
g.ground(0);                                              // a floor at y = 0

Styles are optional. Widths are in pixels, everything else in metres. Sim.colors holds a small palette (blue, red, green, orange, purple, teal, gray, ink, muted), and Sim.palette is the same colours as an array for colouring many things.

Vectors

Most early chapters use small 2D vectors as plain {x, y} objects, with helpers on the global V:

const a = V.v(1, 2), b = V.v(3, -1);
V.add(a, b);          // {x: 4, y: 1}
V.sub(a, b);          // a - b
V.scale(a, 2);        // 2a
V.addScaled(a, b, h); // a + h b, handy for integration
V.dot(a, b);          // 1*3 + 2*(-1) = 1
V.cross(a, b);        // the 2D cross product, a scalar: 1*(-1) - 2*3 = -7
V.len(a); V.norm(a); V.perp(a); V.dist(a, b); V.lerp(a, b, t); V.rotate(a, angle);

They return new objects, which is clear and fast enough for a few hundred particles. The particle-grid chapters, with thousands of particles, switch to flat typed arrays (xs[i], ys[i]) for speed.

Controls, readouts and the mouse

Controls are created at the top level of your script, before Sim.run, and appear in the panel to the right of the canvas. Each returns an object whose .value is always current, so you read it wherever you need it:

const k = Sim.slider('stiffness k (N/m)', 0, 1000, 100);         // min, max, start
const alpha = Sim.logSlider('compliance', -8, -2, 1e-5);           // powers of ten, for wide ranges
const gravity = Sim.checkbox('gravity', true);
const method = Sim.select('method', ['PBD', 'XPBD'], 'XPBD', { reset: true });
Sim.button('kick', () => { ball.vx += 2; });

Passing { reset: true } restarts the scene when the control changes, which is what you want for anything that changes the setup (the number of particles, the method), as opposed to a parameter you want to change live.

Two readouts help you see what your simulation is doing. Call both from draw:

Sim.show('energy (J)', E);                          // a line in the info box, this frame
Sim.plot('energy', E, { color: Sim.colors.red });   // a scrolling graph, one sample per frame

Plots are the most underrated debugging tool in simulation. A number that should stay constant (energy, length, momentum) and does not is the first sign of a bug, and a plot shows you exactly when it started.

The mouse is in world coordinates too: Sim.mouse.x, Sim.mouse.y, Sim.mouse.down, and Sim.mouse.pressed / Sim.mouse.released, which are true for the single frame on which the button went down or up. That is all you need to pick up and drag particles, which many demos let you do.

Your turn

bring the starter to life

Open the starter (run it, read it). The dot does not move. Fix the three TODOs:

  1. In step, advance the angle by the angular speed times dt.
  2. In draw, when the mouse is over the canvas, draw an arrow from the dot to the mouse and show its length.
  3. Plot the dot's x and y.

Before you run it: what shape will the two plots have, and how will they be shifted relative to each other?

Hint: the arrow

g.arrow(x, y, dx, dy) takes the start point and the vector, not the end point. The vector from the dot p to the mouse is V.sub(V.v(Sim.mouse.x, Sim.mouse.y), p).

Solution

See solution.js. The interesting lines:

function step(dt) {
  angle += speed.value * dt;
  // ...
}

// in draw(g):
const m = V.v(Sim.mouse.x, Sim.mouse.y);
if (Sim.mouse.inside) {
  const d = V.sub(m, p);
  g.arrow(p.x, p.y, d.x, d.y, { color: Sim.colors.orange, width: 2 });
  Sim.show('distance to mouse', V.len(d), 3);
}
Sim.plot('x', p.x, { color: Sim.colors.blue });
Sim.plot('y', p.y, { color: Sim.colors.red });

The plots are a cosine and a sine: the same wave, a quarter of a turn apart.

make it yours

Three small changes, each using a different part of the sandbox:

  1. Make the dot follow the mouse while the button is held, and return to the circle when released.
  2. Add a slider that changes the step size (dt), and watch what happens to the motion at large steps. Is the dot still on the circle? (It should be: we compute the position from the angle exactly. Remember this; it is not true of physics, as the next two chapters will show.)
  3. Draw a ring of twelve dots with g.points from two Float64Arrays.

Summary

  • A script is reset, step(dt) and draw(g), started with Sim.run. State lives in your variables; step changes it, draw only looks.
  • Everything is in metres with y up. view chooses what you see.
  • Controls return objects with a live .value; { reset: true } restarts the scene on change.
  • Sim.show and Sim.plot are your instruments. Use them on every quantity that should be conserved.
  • Space, . and R pause, single-step and reset. Errors pause the run and appear on the canvas.
